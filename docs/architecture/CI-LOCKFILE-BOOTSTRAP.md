# Reproducible workspace installs

The repository uses pnpm 9.15.4 and a committed root `pnpm-lock.yaml` for the complete workspace. CI installs with `pnpm install --frozen-lockfile`; Vercel projects are temporarily configured to install without frozen lockfile while PRs are reconciled.

The lockfile was generated by the trusted CI workflow using the declared root and workspace manifests. The lockfile must be regenerated with the pinned pnpm version whenever any workspace manifest changes:

```sh
corepack pnpm@9.15.4 install --lockfile-only
corepack pnpm@9.15.4 install --frozen-lockfile
```

Do not commit credentials, generated environment files, or deployment artifacts. The lockfile is a dependency resolution artifact, not a substitute for security review, dependency update policy, or software composition analysis.

## Acceptance checks

- A clean checkout can install with frozen lockfile.
- CI typecheck, tests, OpenAPI drift validation and build pass after the install.
- Every package manifest change is reflected in the lockfile.
- Web and API Vercel projects use the same pnpm version and Node 22 runtime.
